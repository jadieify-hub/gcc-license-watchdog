# GCC License Watchdog

Небольшая служба Windows, которая освобождает зависшие лицензии Guardant: следит за локальным Guardant Control Center (GCC) и перезапускает его, когда все лицензии компонента заняты и среди подключений есть повтор пользователя.

Разработчик: Руслан Керусов. Издатель и владелец: KRS. © 2026 KRS.

## Скачать и установить

Официальные установщики находятся в [GitHub Releases](https://github.com/jadieify-hub/gcc-license-watchdog/releases/latest). Скачайте файл `GCC-License-Watchdog-Setup.exe` из раздела Assets.

Устанавливайте Watchdog **на компьютер, где находится сам ключ или локальная программная лицензия**, а не на рабочие места, получающие лицензию по сети.

1. Убедитесь, что установлен GCC и открывается `http://localhost:3189`.
2. Запустите установщик с правами администратора.
3. В `services.msc` проверьте, что служба `GCC License Watchdog` работает.

Установщик создаёт службу от имени `LocalSystem` с автоматическим отложенным запуском после включения компьютера и восстановлением при сбое. Открывать отдельную программу или держать пользователя в системе не требуется.

Установщик пока не имеет цифровой подписи: Windows может показать предупреждение.

## Требования

- Windows 10/11 или Windows Server 2016/2019/2022/2025 в редакции, совместимой с [.NET 8](https://github.com/dotnet/core/blob/main/release-notes/8.0/supported-os.md). Сборка `win-x86` работает на Windows x86 и x64; ARM отдельно не проверялся.
- Установленный Guardant Control Center с доступным локальным REST API на порту `3189`. Интеграция проверялась с GCC **4.0.5.3**; совместимость API других версий нужно проверять отдельно.
- Локальный ключ или программная лицензия с сетевым ресурсом.
- Права администратора для установки, обновления и изменения настроек.

.NET включён в установщик; отдельно устанавливать его на клиентский компьютер не нужно. Постоянный доступ в интернет для работы службы не требуется.

## Как работает

По умолчанию проверка выполняется каждые 30 секунд. Перезапуск происходит при одновременном выполнении условий:

- компонент использует локальную сетевую лицензию;
- свободных лицензий этого компонента нет;
- у одного пользователя обнаружено несколько разных сессий в том же ключе, продукте и компоненте.

Пользователи сравниваются по ID **или** видимому имени. При сравнении имён не учитывается регистр, пробелы по краям и цифровой суффикс вида `(12345)`. Повтор одной и той же записи сессии не считается дополнительным подключением.

Если все пользователи разные, перезапуска не будет. Сообщение о заполнении компонента записывается один раз за непрерывный период заполнения в пределах текущего запуска Watchdog. После освобождения и нового заполнения запись может появиться снова.

Watchdog проверяет остановку GCC, повторный запуск и доступность API. Если GCC уже остановлен, служба пытается его запустить. Между успешными перезапусками действует пауза **5 минут**, которая сохраняется после перезапуска Watchdog.

Обычная остановка или удаление Watchdog дожидается завершения уже начатого восстановления GCC в пределах тайм-аутов. При стандартных настройках остановка наблюдателя в таком случае может занять до нескольких минут.

## Обновление и удаление

Для обновления запустите новый официальный установщик поверх установленной версии. Конфигурация, журналы и время последнего успешного восстановления сохраняются. Служба Watchdog будет остановлена и запущена вновь.

Для удаления используйте «Параметры → Приложения», «Программы и компоненты» или «Пуск → GCC License Watchdog → Удалить GCC License Watchdog». Можно выбрать, сохранить или удалить настройки и журналы. Тихое удаление сохраняет их автоматически.

## Настройки и журналы

- Настройки: `%ProgramData%\GCC License Watchdog\appsettings.json`.
- Журналы: `%ProgramData%\GCC License Watchdog\logs\watchdog-*.log`.
- Критические ошибки дополнительно записываются в журнал Windows «Приложение» от источника `GCC License Watchdog`.

В конфигурации раздел `Watchdog` задаёт интервал проверки, паузу между восстановлениями и тайм-ауты. Значения времени имеют единицы измерения в названиях: `Seconds` — секунды, `Minutes` — минуты.

Общий уровень журнала задаётся в `Logging:LogLevel:Default`: `Information` по умолчанию, `Warning` для предупреждений и ошибок, `Debug` для диагностики. Отдельные настройки категорий имеют приоритет: для HTTP-запросов задан `System.Net.Http.HttpClient: Warning`, для сообщений запуска и остановки хоста — `Microsoft.Hosting.Lifetime: Information`. Чтобы оставить только предупреждения и ошибки, установите `Warning` также для `Microsoft.Hosting.Lifetime`. Для диагностики HTTP измените его категорию на `Debug`. После изменения настроек перезапустите Watchdog через `services.msc`.

Создаётся новый файл каждый день или после достижения 10 МБ; сохраняются последние 14 файлов, а не обязательно 14 дней.

Посмотреть последние записи и продолжить наблюдение в PowerShell:

```powershell
$log = Get-ChildItem "$env:ProgramData\GCC License Watchdog\logs\watchdog-*.log" |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
if ($log) { Get-Content -LiteralPath $log.FullName -Encoding UTF8 -Tail 50 -Wait }
```

После смены файла запустите команду снова. Проверить состояние служб:

```powershell
Get-Service -Name 'Guardant Control Center','GCC License Watchdog'
```

## Ограничения и сообщения о проблемах

Повтор пользователя — практический признак зависших сессий, а не доказательство. Несколько законных подключений одного пользователя, одинаковые имена у разных людей или значимые цифры в скобках могут вызвать лишний перезапуск. Зависшие сессии разных пользователей автоматически не распознаются. При единственной занятой лицензии и единственной сессии повтора нет, поэтому перезапуска не будет.

Watchdog видит только сессии, которые показывает API GCC, независимо от способа входа в прикладную программу. Проблемы лицензирования самой платформы 1С он не исправляет. Перезапуск GCC затрагивает все обслуживаемые им лицензии. Принудительное завершение процесса Watchdog, выключение питания или неисправность GCC могут помешать восстановлению; гарантировать запуск в этих случаях невозможно.

Сообщайте о проблемах через [GitHub Issues](https://github.com/jadieify-hub/gcc-license-watchdog/issues). Укажите версии Watchdog, GCC и Windows, ожидаемый результат и фрагмент журнала. Перед публикацией удалите из журнала имена пользователей, идентификаторы ключей и другую информацию клиента.
